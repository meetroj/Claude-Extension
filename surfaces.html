Allowed — draw freely

2Activity barYour own icon and container via contributes.viewsContainers.activitybar. A number badge on it. The icon itself cannot animate.
3Primary sidebarregisterWebviewViewProvider — a full HTML page. Every pixel inside it is yours.
6Editor text areacreateTextEditorDecorationType — text or an image before, after, or on top of any line; gutter icons; CodeLens above a line; inlay hints; hovers; line and background colors.
10Bottom panelSame webview view, in viewsContainers.panel. Its tab title and its badge are both writable at runtime — the two escalation rungs in IDEA.md.
11Secondary sidebarNot a separate contribution point. A view you contribute elsewhere can be dragged here by you, and it stays.
12Status barcreateStatusBarItem. Text, codicons, a background color. You pick left or right and a priority number — not a pixel position.
—Editor as a tabcreateWebviewPanel opens a tab holding a real web page. The one place with genuinely free pixel movement — at the cost of an editor slot.
—NotificationsshowInformationMessage, withProgress. Bottom-right toasts. The last rung on the ladder.
—File tree labelsregisterFileDecorationProvider — a badge and color on filenames in the Explorer.

Reachable, but by a side door

1Window title barNo API. But VS Code renders it from the window.title setting, and an extension can rewrite that setting on a timer. Costs a settings.json write per frame, and it is global to every window.
5Tab bar, far rightA menus.editor/title command icon lands beside the split and ⋯ buttons. It can change; it cannot move. VS Code owns its position.
8Overview ruleroverviewRulerLane paints colored ticks in the scrollbar track. Colors only — no shape, no image, no emoji.

Locked — no API exists

4Tab bar & breadcrumbsTab labels, tab order, the breadcrumb row. You can set the title of a webview you own, and nothing else.
7MinimapRendered by VS Code from the document. Nothing can be drawn into it.
9Window controls & menu barNative OS chrome. Out of reach entirely.
13The gaps between panesBorders, splitters, the space between the editor and the sidebar. This is what stops one pet from sliding around the window — there is no surface in between to walk on.
—A free-floating overlayDrawing on top of the whole workbench. Only patching workbench.html reaches it: triggers the "installation is corrupt" warning, breaks on every VS Code update, cannot be published to the Marketplace.
—Another extension's webviewThe Claude Code and Codex chat panes are sandboxed iframes. No extension can inject into another's DOM.
The practical consequence for Oi: a pet cannot travel continuously around the window, because zone 13 has no floor. It can either roam freely inside one surface, or teleport between several. Those are the only two shapes available.
